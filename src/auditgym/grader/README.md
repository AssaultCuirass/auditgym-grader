# Оценщик AuditGym

В доверенном раннере создайте `GraderClient(data_root, log_dir=...)` и передайте его в `AuditEnv`. Поддерживаются каталог одного эпизода и хранилище с дочерними каталогами по `episode_id`. На Windows запуск раннера должен находиться под `if __name__ == "__main__":`.

```python
with GraderClient(data_root, log_dir=log_dir) as grader:
    result = grader.submit(episode_id, findings_envelope, inspection_steps)
```

`findings_envelope` содержит `episode_id` и список `findings`. Среда вызывает `submit` один раз на завершение. Она передаёт `None` только при тайм-ауте. Счётчик включает все предыдущие инспекции. В рабочем процессе используется `grade(episode_dir, findings, inspection_steps)` из §9.6. Ключ сопоставляется с публичным манифестом. Полный `GradeResult` с парами `(issue_id, индекс)` записывается в закрытый `grader.jsonl`. В ответе клиенту поле `matches` пустое. В `train` среда выводит поля §8.5, в `eval` возвращает пустой `info` и нулевую награду.

Для изоляции файловой системы интегратору нужны разные UID для среды и оценщика. Spawn наследует права запускающего процесса. Доверенный раннер должен запустить оценщик с доступом к ключам и закрытым логам до запуска недоверенной политики с ограниченными правами. Каталоги эпизодов и логов должны контролироваться раннером.

## Проверка отдельного репозитория

Из корня репозитория на Python 3.11:

```shell
uv run --project tests/grader --frozen pytest -c tests/grader/pyproject.toml -q tests
```

Для проверки совместимости добавьте `src` репозитория генератора в `PYTHONPATH`. Тест строит 50 эпизодов, подаёт эталонные ответы через IPC и проверяет видимые данные и действие `AUDITGYM_SALT`. Для двух тестов завершения нужен `auditgym.env.core.AuditEnv` роли 2. Эти зависимости проверяются при сборке совместного проекта.

## Проверка траектории

После запуска политик передайте сканеру каталог эпизода и JSONL. Если файл содержит несколько эпизодов, вызовите сканер для каждого. Запускайте проверку в доверенном процессе с `src` в `PYTHONPATH`.

```shell
python -m auditgym.grader.leakage data/dev/ep_00 runs/example/trajectories.jsonl
```

Сканер проверяет вложенные поля `observation`, `obs`, `info` и `error` и сообщает номер строки при утечке. Он сравнивает строки эталона и provenance с шестью открытыми файлами, включая публичные ссылки на документы, проводки и курсы. Поля эталона, служебные маркеры и абсолютные пути проверяются отдельно. Если seed совпадает с обычным открытым числом, принадлежность устанавливается по контексту, например по имени поля `seed`. Для проверки значения секретной соли запустите сканер с той же `AUDITGYM_SALT`, что и генератор.

Для проверки всего набора задайте `AUDITGYM_TEST_EPISODES` (каталог эпизодов) и `AUDITGYM_TEST_RUNS` (каталог прогонов). Тест `test_policy_trajectories.py` сканирует все записи и проверяет наличие завершённых траекторий четырёх политик на одних и тех же 50 эпизодах. Отдельный тест среды сравнивает ошибки для удалённого и выдуманного ID.

Таблица с измеренными наградами находится в [tests/attacks/README.md](../../../tests/attacks/README.md).
